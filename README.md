# 🕌 Бот времён намазов — Нижневартовск

Telegram-бот с расписанием намазов и уведомлениями.

## Файлы проекта

```
prayer_bot/
├── bot.py                              # основной код бота
├── prayer_times_nizhnevartovsk.csv     # расписание намазов
├── requirements.txt                    # зависимости
├── migrate_users.py                    # одноразовый перенос старых users.json → Postgres
├── Procfile                            # для Railway
└── README.md
```

Данные пользователей хранятся в **Postgres**, а не в файле — это переживает
деплои (раньше файл `users.json` стирался при каждом обновлении кода).

## Деплой на Railway

### 1. Подготовка GitHub

1. Создай новый репозиторий на [github.com](https://github.com)
2. Загрузи файлы: `bot.py`, `prayer_times_nizhnevartovsk.csv`, `requirements.txt`, `Procfile`

### 2. Деплой на Railway

1. Зайди на [railway.app](https://railway.app) → Sign in with GitHub
2. Нажми **New Project** → **Deploy from GitHub repo**
3. Выбери свой репозиторий
4. В том же проекте нажми **New** → **Database** → **Add PostgreSQL**
5. Перейди в сервис бота → **Variables** и добавь:
   - `BOT_TOKEN` = твой токен от BotFather
   - `DATABASE_URL` = нажми **Add Reference** → выбери переменную `DATABASE_URL` из сервиса Postgres
     (Railway сам подставит правильную строку подключения)

### 3. Запуск

В разделе **Settings** убедись что тип сервиса — **Worker** (не Web).
Railway автоматически запустит бота и создаст таблицу `users` при первом старте.

### 4. Перенос старых пользователей (нужно один раз)

Если бот уже работал раньше на файле `users.json` и вы хотите сохранить текущих
пользователей:

1. **До** обновления кода — зайдите в Railway → сервис бота → **Deployments** →
   откройте активный деплой → **Shell**, выполните `cat users.json` и
   скопируйте содержимое.
2. Сохраните его локально в файл `users_backup.json` рядом с `migrate_users.py`.
3. Задеплойте новую версию кода (с Postgres).
4. Локально выполните:
   ```bash
   DATABASE_URL="<значение из Railway → Postgres → Variables → DATABASE_URL>" \
   python migrate_users.py
   ```
   Скрипт перенесёт всех пользователей из бэкапа в базу.

## Доступ к данным пользователей

Теперь можно подключиться к базе напрямую (не через бота) любым Postgres-клиентом
(TablePlus, DBeaver, psql) — строка подключения лежит в Railway →
сервис Postgres → **Variables** → `DATABASE_URL` (или `DATABASE_PUBLIC_URL`
для подключения снаружи Railway).

Таблица `users`:

| Колонка | Тип | Описание |
|---|---|---|
| user_id | BIGINT | Telegram ID пользователя |
| username | TEXT | @username (может отсутствовать, если не задан в Telegram) |
| first_name | TEXT | имя из профиля Telegram |
| last_name | TEXT | фамилия из профиля Telegram (может отсутствовать) |
| notifications | BOOLEAN | уведомления включены/выключены |
| notify_start | BOOLEAN | уведомление в момент намаза |
| notify_15 | BOOLEAN | уведомление за 15 минут до конца |
| prayers | JSONB | какие намазы включены |

Имя/username/ID заполняются автоматически при **любом** сообщении или нажатии
кнопки — не только по `/start`. Это же попутно "находит" пользователей,
потерянных при прошлых обновлениях: как только человек снова напишет что угодно
боту, он опять появится в базе.

В боте также остаётся команда `/stats` (только для админа) — теперь она
выводит ID + имя + @username по каждому пользователю, а не только ID.

## Локальный запуск

```bash
pip install -r requirements.txt
BOT_TOKEN=ваш_токен python bot.py
```

## Команды бота

| Команда | Описание |
|---------|----------|
| /start | Главное меню |
| /today | Намазы на сегодня |
| /next | До следующего намаза |
| /month | Расписание на месяц |
| /notifications | Настройки уведомлений |

## Уведомления

- 🔔 При наступлении каждого намаза
- ⏰ За 15 минут до окончания времени намаза  
- 🕌 Напоминание о Джума каждую пятницу в 12:00
- Можно включать/выключать по отдельным намазам

## Чистый чат

Каждый новый текстовый ответ бота и каждое новое уведомление удаляет предыдущий
текстовый ответ в личном чате после успешной отправки и сохранения его номера.
Ответы, разбитые на части, сохраняются вместе до следующего ответа. Номера
хранятся в Postgres и переживают перезапуск. Виджеты и сообщения пользователя
не удаляются. Правило действует на сообщения, отправленные после установки
обновления; старую переписку оно не очищает. Telegram обычно не позволяет
удалять сообщения старше 48 часов; ошибка удаления не мешает отправке нового.

После успешного ответа на команду или кнопку бот удаляет сообщение пользователя,
которое вызвало этот ответ. Неизвестный текст, команды без ответа и команды с
ошибкой сохраняются. Удаление действует только в личных чатах.

## Живой виджет

Кнопка «🕌 Время намазов», команды /widget и /next присылают виджет. /start
показывает его новым пользователям. Прежняя кнопка «Следующий намаз» тоже
поддерживается. /today всегда присылает текстовое расписание; если отправка
виджета недоступна, команды автоматически отвечают текстом.

Утверждённое оформление: один столбец, основной цвет текста для таймера,
тонкая отметка текущего намаза со словом «Сейчас» под названием. «Время для дуа»
появляется по пятницам за 60 минут до Магриба и исчезает с его наступлением.
Виджет самостоятельно обновляет дату и отсчёт в UTC+5 без доступа к сети.

Отправка использует проверенный адрес Telegram /beta/bot<TOKEN>/sendWidget.
Она не зависит от Catalogue. Предыдущий виджет удаляется только после
успешной отправки нового и сохранения его номера в user_widgets. Обычные
уведомления не удаляют виджет. Логи HTTP-запросов с токеном отключены.

Для однократного запуска существующим пользователям: python rollout_widgets.py
сначала показывает число получателей; --send выполняет отправку. Повторный
запуск пропускает пользователей, которым уже доставлена эта версия виджета.
